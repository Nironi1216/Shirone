# 把博客搭起来这件事

现在手机端打开是这样：

![手机端首页](/images/posts/building-this-blog/home-mobile.webp)

从 fork 主题到绑上自己的域名拢共没几天，坑倒是不少。记一下，免得过两个月我自己都忘了当初为什么这么配。

## 先得有个能跑起来的环境

主题用的是 [Shirone](https://github.com/LyraVoid/Shirone)，Astro 7 + Svelte 5 + Tailwind 4，白净、克制，一眼就喜欢。

第一步就卡住了：这台机器没装 Homebrew，`/usr/local` 也不可写，`brew install node` 走不通。最后是去 Node 官网下 tarball 解压到 `~/.local/nodejs`，再把路径写进 `.zshrc`。pnpm 用 npm 全局装。SSH 密钥换成 ed25519。

都不是什么大事，但每换一次机器就得重新折腾一遍。

## 让它变成"我的"

先做中文化：站点语言、站名 `Neyuuのblog`、副标题「人间漫游」。主题自带的演示文案清得很干净，可换成自己的话之后，那种"这是我的地方"的感觉才真的出来。

壁纸挑了堆糖上焦茶的一组图，桌面 1920×1080、手机 1080×2340 各裁一套：

![四张手机端壁纸的裁切结果](/images/posts/building-this-blog/wallpaper-mobile.webp)

裁切比想象中麻烦。脚本按 `attention` 策略自动取景，插画类的还行，有人物的那几张会把脸切掉一半。最后有几张是手动指定焦点、左右挪过取景才救回来的。机器判断"哪里重要"这件事，碰上有人物的画面还是不太靠得住。

## 字体那点事

本来只想给横幅标题换个字体。换成霞鹜文楷之后觉得全站中文都该是这个味道，于是又铺开到整站，顺手把原来的悠哉圆体删了。

![同一段标题，换字体前后](/images/posts/building-this-blog/font-compare.webp)

这里连踩三个坑：

1. 用了 npm 包，字却没变。那个包的 `unicode-range` 只覆盖汉字，拉丁字母和假名不在里面，浏览器自然不命中。最后改成自托管子集。
2. 改了 CSS，页面纹丝不动。是 Vite 的缓存。改 `siteConfig` 或者被 `@import` 引用的子 CSS，都得重启 dev server 才生效。这条浪费了我十几分钟。
3. 子集字表不好生成。想按 GB2312 取字，Node 不支持 gb2312 解码，最后是拿 Python 生成的字表，7541 个字，压完 3.5MB。

## 把演示数据换成真的

主题自带的东西很多：55 篇示例文章、系列、技能、游戏、项目、时间线。全清了。

关于页重写，设备页填了五台真正在用的设备。填的时候纠结过要不要写价格，最后全删了，一个记录"我用什么"的页面不该变成价目表。描述也尽量说人话，比如手机那条写的是"225g，放裤兜里会往下坠"，而不是"轻薄便携，握持舒适"。

![设备页填好之后的样子](/images/posts/building-this-blog/devices.webp)

番剧页接了 B 站的追番列表，77 部：

这里有个坑值得记一笔：抓下来的快照和封面被 `.gitignore` 挡在仓库外面，本地看着好好的，一上线就退回演示数据。查了半天才反应过来，"本地有"和"线上有"是两件事，中间隔着 .gitignore。放开规则重新提交才修好。

## 部署，以及"我以为它没生效"

Vercel 导入仓库，绑域名 `neyuu.fun`，全程没什么可说的。有两个小地方：

- `siteConfig.site` 必须写成自己的域名。写错的话 og 链接、RSS、sitemap 全指向别处，而且这种错误在本地完全看不出来。
- 推送之后不是立刻生效，大约要等 5 分钟。我第一次以为部署失败了，反复刷，其实它在排队。

验证移动端布局时也误判过一次：直接用 `--window-size=390,844` 截图，看起来卡片右边缘被切了，以为有横向溢出。后来用 CDP 的设备仿真实测，`scrollWidth` 是正常的 390。窗口尺寸和设备仿真不是一回事，前者会骗人。

## 为了"随手发条动态"，绕了三圈

这块折腾最久，也最没用，但过程挺有意思。

**第一圈**：做了个网页，在里面填 GitHub Token 就能直接发动态。做完自己都觉得鸡肋，每次发东西还要去翻一遍 Token，那还不如开电脑写。

![第一版的发动态页面，后来整个回退了](/images/posts/building-this-blog/publish-draft.webp)

**第二圈**：改成账号登录，邮箱加密码，登录后由服务端代写 GitHub。写到一半又放弃了，因为这意味着要引入一个运行时。一个静态博客为了发条动态去养个后端，怎么看都本末倒置。

**第三圈**：最后定下来的方案是把社交 App 当输入法。手机上在 Mastodon 或者 Telegram 发消息，构建时抓回来变成动态。站点还是纯静态，没有服务端、没有登录、没有数据库。发完要等下一次构建才看得到，这点没法回避，但那本来就是静态站该有的样子。

绕完这三圈我现在的想法是，想给静态站加一个"动态"的功能时，先问问是不是非得把它变成动态站。大部分时候答案是不用。

（顺带一提，这个方案现在默认关着，等哪天真的开始用了再开。）

## 最后

站搭好了，内容还空着大半。设备页有东西了，番剧页有东西了，剩下的慢慢填。

至少现在打开 neyuu.fun，能看到写着我自己名字的地方了。
